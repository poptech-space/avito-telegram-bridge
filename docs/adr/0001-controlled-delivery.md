# 0001. Управляемая доставка Avito bridge

Дата: 2026-10-29. Статус: принято локально, облачная приёмка отдельно.

## Контекст

Переменная последнего диалога в памяти serverless-экземпляра не обеспечивает
правильную адресацию. Прямой POST до/после ACK может потеряться или повториться.
Случайный запуск worker после выпуска также может отправить старый backlog.

## Решение

Поддерживать только YCF + YDB до отдельной реализации/приёмки другого runtime.
Проверять источник webhook, затем владельца, private-чат и Reply на своего бота.
Не выбирать последнего покупателя автоматически. Сохранять dedup и задания до ACK;
отправлять вне транзакций после durable claim. Подтверждённый ID даёт sent,
явный отказ — rejected, неопределённый результат — unknown без автоматического повтора.

Worker остаётся приватным и ограниченным lease/количеством заданий/бюджетом времени.
Новый флаг `DELIVERY_ENABLED` выключен по умолчанию. Автоответ — отдельный opt-in.
Перед включением доставки проверить все pending, поскольку переключатель открывает
весь backlog. В коде нет обхода списка пользователей для рассылки.

## Последствия

Нужны клиентская БД, worker, таймер, мониторинг и адресное восстановление. Таймер
увеличивает задержку и создаёт вызовы без входящих сообщений. Выключатель не отменяет
уже начатую отправку. Exactly-once не обещается, unknown может потребовать ручной сверки.
Лимит 100 submissions на запись остаётся ограничением пилота; перед постоянной
эксплуатацией нужна другая модель истории с сохранением активных/неизвестных заданий.

Существовавшие локальные изменения YDB/outbox сохраняются и уточняются; этот ADR
не является подтверждением их публикации или выкладки. Общее решение workspace:
`bots/docs/adr/0002-durable-state-and-delivery.md` (не требуется для отдельного клона).
